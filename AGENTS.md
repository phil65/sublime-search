# AGENTS.md

## Overview

`sublime-search` is a Python package backed by a Rust extension (PyO3 + maturin). It
provides Sublime Text style fuzzy matching, a multi-strategy fuzzy search-and-replace
for LLM code-editing tools, a locationless unified-diff parser/applier, and a streaming
matcher that locates text while it is still arriving. Not copier-managed.

## Architecture

```
src/lib.rs                 PyO3 bindings: #[pymodule] _sublime_search, fuzzy_match /
                           get_best_matches / fuzzy_match_simple (implemented inline),
                           Python-facing result classes, RetryableError, error mapping
src/content_replacer.rs    replace_content(): 8 replacer strategies tried in order
                           (simple, line_trimmed, block_anchor, whitespace_normalized,
                           indentation_flexible, escape_normalized, trimmed_boundary,
                           context_aware), fuzzy "closest match" diagnostics, trim_diff
src/diff_parser.rs         parse_locationless_diff(), apply_diff_hunks(_with_hint):
                           each hunk is applied via content_replacer::replace_content
src/streaming_matcher.rs   StreamingFuzzyMatcher: line-based edit-distance search matrix,
                           incremental push()/finish(), line-hint selection
python/sublime_search/__init__.py          re-exports; thin Python wrappers (with
                                            docstrings) for the three fuzzy_* functions
python/sublime_search/_sublime_search.pyi  hand-written stubs for the extension module
python/sublime_search/py.typed
tests/                     pytest suite (Python API); Rust unit tests live in
                           `mod tests` at the bottom of each src/*.rs file
examples/streaming_matcher_demo.py
```

Rust↔Python boundary:
- Pure-Rust types (`content_replacer::ReplaceResult`, `diff_parser::DiffHunk`, ...) are
  converted to `#[pyclass]` wrappers in `lib.rs` via `From` impls. Fields are exposed with
  `#[pyo3(get)]` (read-only).
- Error mapping in `lib.rs`: `NotFound` / `MultipleMatches` / `NoHunksApplied` ->
  `RetryableError` (subclass of `Exception`, not `ValueError`); `NoChange` /
  `NoHunksFound` -> `ValueError`. Empty `old_string` is reported as `NotFound`
  (so `RetryableError`). `try_*` variants never raise.
- Line numbers in results are 1-based; `MatchRange` offsets are byte offsets.
- Some pyclasses are renamed (`#[pyclass(name = "DiffHunk")]` on `PyDiffHunk`, etc.).

## Where to look

| Task | File |
|------|------|
| Add/export a Python function or class | `src/lib.rs` (`#[pymodule]` at bottom), then `python/sublime_search/__init__.py` (`import` + `__all__`) and the `.pyi` stub |
| Replacement strategy behaviour/thresholds | `src/content_replacer.rs` (constants at top) |
| Diff parsing (tags, code fences, headers) | `src/diff_parser.rs` |
| Streaming match costs / line hints | `src/streaming_matcher.rs` |
| Fuzzy scoring | `fuzzy_match` in `src/lib.rs` |
| Wheels / release | `.github/workflows/build.yml` |
| Version | `Cargo.toml` (`[package] version`; pyproject uses `dynamic = ["version"]`) |

## Commands

```bash
cargo build
cargo test                 # Rust unit tests (no Python needed)
cargo clippy --all-targets
cargo fmt
uv sync                    # builds the extension into .venv via maturin
uv run pytest              # conftest runs `maturin develop --release` first (maturin is in the dev group)
SKIP_RUST_BUILD=1 uv run pytest   # skip the rebuild, e.g. right after `uv sync`
uvx maturin build --release --out dist --find-interpreter   # what CI does per platform
uvx maturin sdist --out dist
```

After changing Rust code, rebuild before running pytest (`uv sync --reinstall-package
sublime-search` or let conftest run `maturin develop`).

## Conventions

- Keep the `.pyi` stub in sync with `lib.rs` signatures/defaults (`#[pyo3(signature = ...)]`)
  and docstrings; the stub is not generated.
- Python tests: plain pytest, classes grouped per feature, `from __future__ import annotations`.
- Rust edition 2021; format with `cargo fmt`. Truncate strings by `chars()`, never by byte
  slicing (`&s[..n]` panics on multibyte text).

## Pitfalls

- CI (`build.yml`, generated by `maturin generate-ci` and edited) only builds wheels for
  Linux/musllinux/Windows/macOS plus sdist; it does not run cargo tests, clippy or pytest.
  Run them locally.
- Release: pushing a tag runs the `release` job, which publishes to PyPI with
  `PYPI_API_TOKEN`. Windows/macOS jobs list Python versions explicitly (`--find-interpreter`
  only finds installed ones); update them when adding a Python version.
- `Cargo.lock` is tracked even though `.gitignore` lists it; `uv.lock` is untracked.
- PyO3 `extension-module` is enabled both in `Cargo.toml` and `[tool.maturin] features`.
- No docs site; the README is the documentation.
